# ScreenCode v1 码制说明

本文是发送端（`client`）与接收端（`server`）的共同契约。任何一侧修改都必须同步改这里，
并由 `screencode` crate 的单元/往返测试兜底。

## 1. 为什么不用 QR

- 标准 QR 单码上限 2953 字节（v40-L），一屏最多几 KB，做「单张高密度」没有意义。
- 同机窗口抓屏（`PrintWindow`）是**近无损数字通道**：没有透视、没有镜头模糊、没有光照，
  唯一的不确定性是「窗口是否按 1:1 渲染」以及局部遮挡。
- 因此自研一套「固定网格 + 黑边框 + 自描述帧头 + 分片 CRC + 文件级纠删码」的码制，
  接收端不找码、直接按坐标采样，单帧容量提升一个数量级。

## 2. 一帧的像素版式

```
PNG: frame_w × frame_h，背景纯白
┌ 白边 MARGIN_MODULES=4 模块 ─────────────────────────────┐
│ ┌ 黑边框 BORDER_MODULES=2 模块 ───────────────────────┐ │
│ │ 帧头 64×16 模块（3 份，每份 40B+CRC32）              │ │
│ │ 数据区：其余内部模块，行优先铺位流                    │ │
│ │   slot0 = idx(4B) + payload(block_bytes) + crc32(4B) │ │
│ └─────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────┘
```

- 模块 = `module_px × module_px` 像素（默认 2）。
- `grid_w = frame_w / module_px - 2*MARGIN_MODULES`（向下取整，右侧/底部可能留 <1 模块的像素）。
- 黑边框坐标：`x<2 || y<2 || x>=grid_w-2 || y>=grid_h-2`。
- 帧头坐标：`[2, 2+64) × [2, 2+16)`，共 1024 位 = 128 字节；写入 3 份 40 字节副本，余下 8 字节置 0。
- 数据区：内部（去掉边框）再扣掉帧头区域的其余模块，按行优先、MSB 在前串成位流。

## 3. 帧头（40 字节，小端）

| 偏移 | 类型 | 字段 |
|---|---|---|
| 0..2 | `"SC"` | magic |
| 2 | u8 | 版本（当前 1） |
| 3 | u8 | 生成时的 module_px（仅参考） |
| 4..6 | u16 | grid_w |
| 6..8 | u16 | grid_h |
| 8..10 | u16 | block_bytes |
| 10..12 | u16 | k（每组数据分片数） |
| 12..14 | u16 | m（每组校验分片数） |
| 14..18 | u32 | total_shards = groups*(k+m) |
| 18..26 | u64 | file_len |
| 26..34 | [u8;8] | SHA-256 前 8 字节 |
| 34..38 | u32 | 对 0..34 的 CRC32 |
| 38..40 | — | 保留 0 |

接收端先读「任意一份 CRC 通过的副本」；三份都坏时用 `--resume` 里缓存的帧头。

## 4. 分片与 slot

```
slot_bytes = block_bytes + 8
[ idx u32 LE ][ payload block_bytes ][ crc32 u32 LE ]   // CRC 覆盖 idx+payload
```

- `idx` 是**全局分片号**，因此 slot 自描述：不需要帧同步，撕裂帧里新旧 slot 各自有效，
  半新半旧的 slot CRC 失败被丢弃。
- 尾部不满一个 slot 的位用 `idx = 0xFFFFFFFF` 的填充 slot 补；接收端直接跳过。
- 接收端按固定 `slot_bytes` 切分数据区位流，所以一个 slot 坏了不会让后面的错位。

## 5. 文件级纠删码

- 文件按 `block_bytes` 切成 `data_blocks = ceil(file_len/block_bytes)` 个数据分片（最后一片补 0）。
- `k = min(100, data_blocks)`，`m = round(k*parity)`（默认 parity=0.10，最小 1，且 `k+m<=256`）。
- 组号 `g = block / k`，组内 `local = block % k`，全局 `idx = g*(k+m) + local`；
  校验分片占 `local = k..k+m-1`。
- 采用 `reed-solomon-erasure` 的 GF(256) 系统码：**任意 k 个分片即可恢复整组**。
- 接收端每组只要 ≥ k 个有效分片就恢复；因此局部遮挡、缩放边缘误差、撕裂都只算「丢分片」。
- `parity > 0` 时，任何一组丢失不超过 m 个分片都能自动补回，无需人工干预。

## 7. 识别流程

1. 灰度化（`0.299R+0.587G+0.114B` 整数近似），Otsu 求阈值。
2. 逐行/逐列统计黑像素，取占比接近最大的连续段作为四条边；
   校验四条边厚度一致（max/min ≤ 1.4）、内部非全黑/全白，得到码框 `rect` 与粗模块尺寸 `m0 = 平均厚度/2`。
3. 在 `rect` 左上角 `(2*m0, 2*m0)` 处按 `m0` 采样 64×16 模块，读 3 份帧头（对尺寸/偏移做少量搜索）。
4. `m = rect.w/grid_w`（与 `rect.h/grid_h` 相差 ≤2%）。
5. 按固定 `slot_bytes` 采样数据区：模块中心 + 上下左右 0.3 模块，多数表决。
6. 每个 slot 过 CRC；`idx` 落库（稀疏文件），够 k 个就做组恢复。

定位失败时可用 `--rect x,y,w,h` 手工指定。

## 8. 兼容与演进

- `version` 字段预留；任何位布局变化都必须升级版本号，并让接收端拒绝不认识的版本。
- 旧 QR 方案（`qr_output/*.svg`、`.qr_session.json`）不再兼容，`server --clean` 会一并清理。
