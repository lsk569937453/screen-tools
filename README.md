# Screen Tools - QR Code File Transfer

基于二维码的文件传输工具，适用于需要在不同设备间通过屏幕扫码传输文件的场景。

## 工作原理

1. **发送端 (Client)**：将文件切片并转换为 Base64，**多线程**生成多个二维码 SVG 文件（结果按序号排序）
2. **展示**：通过 HTTP 服务轮播展示，**默认按原尺寸把当前窗口铺满**（可手动切换每屏张数）
3. **接收端 (Server)**：持续截屏，**一次截屏批量识别同一帧内的多张二维码**，收集并重组还原文件

> 相比逐张展示、逐张识别的旧版本，一屏多张 + 批量收图把有效吞吐提升数倍；
> 生成阶段再叠加多线程，切图速度接近线性提升。

## 编译项目

```bash
# 编译 client
cd client
cargo build --release

# 编译 server
cd server
cargo build --release
```

## 使用方法

### 发送端 (Client)

#### 1. 生成二维码

```bash
cd client
cargo run --release -- <文件路径> [--threads N]
```

示例：
```bash
cargo run --release -- ./test.txt
cargo run --release -- ./big.zip --threads 8
```

该命令会：
- 读取指定文件
- 将文件内容转换为 Base64
- 按 2000 字符切片
- **多线程**生成二维码 SVG 文件到 `qr_output/` 目录（默认线程数 = CPU 逻辑核数，可用 `--threads` 指定）
- 生成完成后**按片段序号排序**输出，保证多线程下文件名、日志顺序与单线程完全一致
- 生成前自动清理 `qr_output/qr_*.svg` 旧文件，避免 `/api/info` 统计到上次的残留

实测（600KB 文件 / 410 张，20 逻辑核）：单线程 12.3s → 多线程 1.1s，约 **10.8 倍**加速，
且两次生成的文件逐字节完全一致。

#### 2. 启动 HTTP 服务

```bash
cd client
cargo run --release
```

服务启动后访问：`http://localhost:9090`

在浏览器中打开页面，点击"开始播放"即可开始轮播。页面特性：

- **一屏多张二维码**，每 300ms 翻一屏
- 默认 **自动（原尺寸铺满）**：SVG 不再放大，按二维码原生尺寸（约 360px，2 像素/模块）计算当前窗口能放下多少张，
  窗口缩放/全屏后自动重算行列与页码（单屏上限 24 张）
- 可手动切换每屏张数：1 / 2 / 3 / 4 / 6，此时会把二维码放大铺满格子（屏小或难识别时更稳）；
  张数越多传输越快，但单张模块像素越少，接收端压力也越大
- 播放时自动隐藏所有面板，把屏幕全部让给二维码；支持全屏
- 支持暂停、重新开始、按片段号跳转、空格播放/暂停、左右方向键翻屏、Esc 退出播放
- 可勾选"循环播放"：收端漏掉的片段会在下一轮自动重扫（不勾选则播完即停）

### 接收端 (Server)

```bash
cd server
cargo run --release
```

程序启动后会：
- 每 50ms 截屏一次（可用 `--interval-ms` 调整）
- **默认按进程 `HSR` 抓取该窗口的客户区**（进程名部分匹配，命中 `HSRClient`）；
  抓的是**后台画面**，窗口可以被其它窗口遮挡，也不需要在前台
- **一次截屏批量识别同一帧内的所有二维码**（一屏 6 张就是一次收 6 个片段）
- 画面与上一帧完全相同时跳过检测，避免轮播间隙空转浪费 CPU
- 收集所有数据片段，同一帧内的重复片段自动去重
- 当 3 秒内无新数据时，自动重组并保存文件（可用 `--idle-timeout` 调整或关闭）

#### 抓取范围

默认行为就是抓 `HSR` 窗口，所以日常只需要：

```bash
cargo run -r                 # 默认抓 HSR 窗口
cargo run -r -- --resume     # 续传，同样默认抓 HSR 窗口
```

目标窗口必须可见且**不能最小化**（后台截图依靠 DWM 渲染，最小化后没有画面）；
窗口被其它窗口盖住没关系，截到的仍是它自己的内容。

需要换目标时：

```bash
cargo run -r -- --list-windows     # 列出所有可见窗口，确认真实的进程名/标题
cargo run -r -- --process chrome   # 按进程名抓（不含 .exe，允许部分匹配）
cargo run -r -- --window 轮播      # 按窗口标题抓（允许部分匹配）
cargo run -r -- --fullscreen       # 抓整块屏幕（旧行为）
```

- 每帧重新读取窗口客户区尺寸，窗口移动/缩放都能跟上
- 窗口被关闭或持续无法截图时会报错退出，并提示具体原因
- `--process` 与 `--window` 可组合（同时满足才匹配），多个命中时优先非最小化且面积最大的窗口

#### 日志

控制台只打印关键信息（启动配置、捕获来源、进度、超时、完成、错误），
全部细节同时写入 `logs/server-<时间戳>.log`，包括：

- 每秒心跳：截屏/识别帧数、网格数、解码成功/失败数、平均耗时、当前片段数、空闲时长
- 每帧识别明细：分辨率、整图/分块/放大重试各自的网格与解码数、漏解与补回数、截屏与识别耗时
- 每个新入库片段的序号、字符数、总数
- 续传启动时列出缺失片段总数与前 20 个序号（控制台与日志文件各一份）
- 窗口客户区变化、后台截图全黑等异常提示
- 会话落盘大小、超时前后的诊断信息

控制台要看到这些明细时加 `-v`（文件里无论如何都有）。

常用参数：

```bash
cargo run -r -- --verbose          # 控制台也输出每帧细节
cargo run -r -- --interval-ms 20   # 更激进的截屏间隔
cargo run -r -- --resume           # 继续上次未完成的会话
cargo run -r -- --idle-timeout 0   # 永不因空闲退出（收满自动结束）
cargo run -r -- --clean            # 清除保存的会话
cargo run -r -- --help             # 完整参数列表
```

接收的文件保存在当前目录下，命名为 `received_file_<时间戳>`

## 典型使用场景

1. 在发送设备上运行 `client` 生成二维码
2. 启动 `client` 的 HTTP 服务，浏览器打开轮播页面
3. 在接收设备上运行 `server`
4. 将轮播页面展示给接收设备的摄像头
5. 等待传输完成，接收文件自动保存

## 技术特点

- **Client**：
  - 文件切片处理，支持大文件传输
  - Base64 编码确保数据完整性
  - **多线程切图**：原子计数器动态领号 + 线程本地收集 + 最终按序号排序，
    输出与单线程逐字节一致；600KB/410 张实测提速约 10.8 倍
  - **一屏多码轮播**：默认按原尺寸铺满（不放大 SVG），也可手动取 1/2/3/4/6 张并放大铺满
  - HTTP 服务实现二维码轮播，SVG 按整数倍模块渲染，尺寸清晰可缩放

- **Server**：
  - 高频截屏（默认 50ms 间隔）
  - **默认按进程 `HSR` 后台抓窗口客户区**（`PrintWindow` + DWM 渲染），窗口被遮挡也能截，
    不抢前台、不改变窗口层级；也可按标题抓或退回整屏
  - **批量收图**：整图检测 + 3×2/2×2 双路分块检测取并集，一帧内的多张码全部解码
    （rqrr 整图检测在密集排列时会漏码；3×2 的瓦片边界可能正好切过一列码，2×2 大瓦片补齐）
  - **放大重试有像素上限**：整帧 2 倍放大超过 1000 万像素时跳过
    （rqrr 0.7 在超大图上遇到假定位图案会空转 17~53 秒，期间不截屏），
    改由分块检测与下一轮轮播补漏；大屏「原尺寸铺满 18 张」时实测收片速度从 7.7/s 提升到 14.4/s
  - 去重机制，避免重复接收；同一帧内的重复片段只入库一次
  - 画面未变化时跳过检测，空转几乎不占 CPU
  - 超时检测，自动判断传输结束；空闲阈值可调，也可以关闭
  - **日志双写**：控制台只留关键信息，`logs/server-<时间戳>.log` 记录每秒心跳、
    每帧识别明细与逐片段入库记录，便于事后定位"为什么没收到数据"
