# Screen Tools - 单张高密度码传输（ScreenCode v1）

通过屏幕显示、同机窗口抓屏来传文件。发送端把文件编码成**一张张高密度网格码图片**（一帧一张），
接收端从 HSR/浏览器窗口的后台截图里按固定网格采样，收满分片后还原文件。

> 与旧版（一屏多张 QR）相比：不再依赖二维码定位图案分组，也不再靠"多轮重扫 + 人工补漏"。
> 单帧容量从约 27 KB 提升到约 98 KB（2505×1329、每模块 2px），
> 并且用**文件级纠删码**自动补回被遮挡/采样错的分片。

- 码制细节：[docs/screencode-v1.md](docs/screencode-v1.md)
- 共享实现：`screencode` crate（生成与识别用同一份版式/帧头/分片代码）
- 发送端：`client`　接收端：`server`

## 工作原理

1. **发送端**：读文件 → SHA-256 → 按 4 KiB 切分片 → 10% 纠删校验 → 规划版式 → 起 HTTP 服务。
2. **播放页**：一次只显示一张 `frame_w × frame_h` 的 1-bit PNG，按设备像素 **1:1** 摆在左上角，
   默认每 300 ms 换一张并无限循环；播放时隐藏所有 UI（任何压在码上的像素都会变成 CRC 失败）。
   码图必须 ≤ 页面可视区：放不下会被裁掉（黑边框不闭合，接收端一直「没有找到码框」），
   页面会用红字提示并拒绝自动播放。
3. **接收端**：持续后台截取目标窗口客户区（默认进程 `HSR`，窗口被遮挡也能截）→
   定位黑色码框 → 读帧头 → 按模块坐标采样 → 每个 slot 自带全局下标与 CRC →
   落盘到分片库 → 每组凑够 `k` 个分片就用 RS 恢复 → 收满后写文件并校验 SHA-256。
4. 丢分片不需要人工处理：只要每组丢失不超过 `m` 个，纠删码自动补回；
   播放端一直循环，漏掉的帧下一轮还会出现。

## 编译

```bash
cargo build --release
```

产物：`target/release/client.exe`、`target/release/server.exe`。

两端的完整用法与示例：`client --help`、`server --help`（也支持 `client help` / `server help`）。

## 发送端

```bash
# 查看 HSR 窗口客户区尺寸（决定 --frame）
client --probe

# 生成并启动播放服务（默认端口 9090）
client <文件路径> --frame auto

# 只导出 PNG 帧，供其它方式把图片塞进窗口
client <文件路径> --export qr_output --frame 2505x1329
```

常用参数：

| 参数 | 默认 | 说明 |
|---|---|---|
| `--frame WxH` / `--frame auto` | 1920x1080 | 目标帧尺寸；`auto` 读 `HSR` 窗口客户区 |
| `--module-px N` | 2 | 每个模块的像素。1 更密（约 4 倍容量）但要求严格 1:1 |
| `--block-bytes N` | 4096 | 分片净荷；越大每帧分片越少、单点损坏粒度越大 |
| `--parity F` | 0.10 | 纠删码冗余比例；0 表示关闭（不推荐） |
| `--dwell-ms N` | 300 | 每帧停留毫秒 |
| `--port N` | 9090 | HTTP 端口 |
| `--process NAME` | HSR | `--frame auto` 时匹配的进程名 |

`--frame auto` 只在「码图正好铺满窗口客户区」时才准；如果播放页开在浏览器里，
真正要匹配的是**页面可视区**（窗口客户区减去浏览器标签栏/地址栏，再减去任务栏），
播放页面面板会打印这个数字（例如 `页面可视区 1912x857`），用那个尺寸生成才能 1:1 放下。
码图大于可视区会被裁掉，**被裁剪**会真的丢数据（黑边框不闭合，接收端会一直报「没有找到码框」），请重新生成。

### 播放页

- 打开 `http://localhost:9090/` 即自动循环播放；`Esc` 退出播放模式，`F` 全屏，空格暂停，方向键翻帧。
- 播放模式只保留码图本身：没有进度条、没有鼠标指针、没有文字覆盖。
- 页面把图片按 `naturalWidth / devicePixelRatio` 放进 CSS 像素，保证 1 个图像像素 = 1 个屏幕像素。
- 想看状态可用 `?debug=1`（右下角显示帧号，但**不要**在正式传输时用）。

## 接收端

```bash
server                    # 默认抓 HSR 窗口，空闲 3 秒且没有新分片时停止
server --resume           # 继续上次的分片库
server -v                 # 控制台也打印每帧细节
```

- 默认按进程 `HSR` 抓**客户区**（部分匹配，能命中 `HSRClient`），走 `PrintWindow` + DWM：
  窗口可以不在前台、被其它窗口遮挡；但不能最小化（最小化后没有画面）。
- 每帧识别细节（码框、实测模块尺寸、槽数、CRC 失败数）写入 `logs/server-<时间戳>.log`；
  控制台只留关键信息，`-v` 时才显示细节。
- 收到新分片会每秒落盘一次到 `.qr_blocks.bin` + `.qr_state.json`，被强杀最多丢 1 秒。
- 全部收满后自动纠删恢复、校验 SHA-256、写出 `received_file_<时间戳>`，成功后清空分片库。

常用参数：

| 参数 | 说明 |
|---|---|
| `--resume` | 续传上次的分片库 |
| `--clean` | 清除分片库（含旧的 `.qr_session.json`）后退出 |
| `--process NAME` / `--window TITLE` | 换目标窗口 |
| `--fullscreen` | 抓整块屏幕（页面上有码也能用） |
| `--rect x,y,w,h` | 手工指定码框（自动定位失败时用） |
| `--interval-ms N` | 截屏间隔，默认 50 |
| `--recheck-ms N` | 画面不变时也重解的间隔，默认 100 |
| `--idle-timeout N` | 无新分片多少秒后停止，0 表示永不 |
| `--out NAME` | 输出文件名 |

## 容量参考

2505×1329 窗口、白边 4 模块、帧头 1024 位、分片 4 KiB：

| 每模块像素 | 网格 | 分片/帧 | 每帧净荷 | 30 MB 需要 |
|---|---|---|---|---|
| 2（默认） | 1244×656 | 24 | 98 KB | 约 350 帧 / 105 s @300ms |
| 1（需严格 1:1） | 2497×1321 | 99 | 406 KB | 约 86 帧 / 26 s |
| 3（更稳） | 827×435 | 10 | 41 KB | 约 850 帧 / 4 min |

实际吞吐还取决于截屏/识别速度（单帧识别约 10~30 ms，取决于窗口大小）。

## 离线校验

不依赖游戏窗口，先确认整条链路：

```bash
cargo run -p client -- ./test.bin --export tmp_frames --frame 800x600
cargo run -p screencode --example verify_frames -- tmp_frames
```

`verify_frames` 会逐帧打印码框/模块尺寸/CRC 失败数，最后做纠删恢复并输出 SHA-256。

## 排查

| 现象 | 处理 |
|---|---|
| 日志「没有找到码框」 | 确认页面真的在目标窗口里、窗口没最小化；试 `--rect x,y,w,h`（码框含黑边框） |
| 截图里明明有码，仍一直「没有找到码框」 | 码图被裁了：浏览器标签栏/地址栏、Windows 任务栏都会吃掉可视区，参考截图里码框只有左边和上边可见（下边框完全没了）就属于这种。按页面面板打印的 `页面可视区 WxH` 重新生成（如 `--frame 1912x856`），或把浏览器 `F11` 全屏 + 任务栏自动隐藏后再生成 |
| 「帧头都校验失败」 | 显示被缩放/裁剪了。用 `client --probe` 取客户区尺寸，`--frame` 与之一致；`--module-px 3` 更稳 |
| 日志「CRC 失败」持续出现 | 局部遮挡（HUD/鼠标/游戏 UI）。把 `--parity` 提到 0.2 重新生成；播放时别让鼠标停在窗口里 |
| 每组缺分片超时 | 提高 `--parity`；确认播放端一直循环、每帧停留 ≥ 300 ms |
| 收完但 SHA-256 不匹配 | 分片库会保留，`--resume` 继续收；仍不匹配请检查显示端是否被缩放 |
| 旧版本产物 | 旧 QR/SVG 与旧 `.qr_session.json` 不兼容；`server --clean` 清掉 |

## 技术特点

- **单张自定义码**：黑边框 + 固定网格 + 3 份自描述帧头；没有 QR 定位图案，也没有多码阵列。
- **确定性采样**：同一份 `Geometry` 生成/识别；1:1 时一次采样即 100% 正确，不依赖"多试几次"。
- **分片自描述**：slot 自带全局下标 + CRC32，撕裂帧、错帧、局部损坏都只影响自己。
- **文件级纠删码**：每组 `k` 数据 + `m` 校验，任意 `k` 个即可恢复；遮挡/缩放误差自动补回。
- **快速识别**：单帧 1~3 万次模块采样 + CRC，约 10~30 ms；对比旧版 rqrr 的 274 ms/帧。
- **后台抓窗口**：`PrintWindow(PW_CLIENTONLY|PW_RENDERFULLCONTENT)`，被遮挡也能截，不抢前台。
